Safe User Sequence

Four wrapper scripts guide you through the full mission-deployment workflow with built-in prompts, descriptions, and safety gates. Run them in order from the repository root.

# Wrapper Script What it does Underlying script
1 Run-StageIncoming.ps1 Finds the newest KMZ in INCOMING, copies it into the chosen role folder, and archives the source so it cannot be re-staged accidentally. Prompts for -Role if not supplied. Step5B — flags: -ArchiveIncoming
2 Run-HealthCheck.ps1 Validates UUID role mapping, inventory alignment, staged KMZ files, and live RC2 slot state. Any WARNING or ERROR blocks deployment. RC2 must be connected via USB. Step9 — flags: -CheckRC2 -FailOnWarning
3 Run-DeployPreview.ps1 Shows the full deployment plan — which KMZ files would go to which RC2 UUID slot folders. No files are transferred, moved, or deleted. Prompts for -Role if not supplied. Step6 — flags: -DryRun
4 Run-Deploy.ps1 Copies staged KMZ packages to RC2 UUID slot folders via MTP. Displays the plan and requires you to type YES before any file is written. Anything else cancels cleanly. Step6 — flags: -PromptBeforeCopy

Each wrapper prints a description of what it will do at runtime, so no prior knowledge of parameter flags is required.

RC2 visual order note: the RC2 mission list is effectively timestamp-driven. For predictable A/B/C display, run full Step6 deploy in order Mission_C -> Mission_B -> Mission_A. In newest-first sort this appears as A, B, C; in oldest-first sort it appears as C, B, A.

RC2 Visual Validation

After deploy, use this quick field check to avoid slot confusion on RC2:

  1. Open mission list and set sort to Newest first; confirm visual order is A, B, C.
  2. Switch sort to Oldest first; confirm visual order flips to C, B, A.
  3. If mission footprint is not obvious, load three test missions with clearly different shapes (for example: triangle, line, box) to make visual identification immediate.
  4. If map does not auto-center mission location, use RC2 map browse/set-location flow and confirm the expected shape before flight.

Scripts

Use the Run-* wrappers for day-to-day operations. The underlying Step scripts are the engine — called automatically by the wrappers.

Wrapper scripts (recommended entry points)

  • Run-StageIncoming.ps1 — guided Step 1: stage INCOMING KMZ to role folder with archive
  • Run-HealthCheck.ps1 — guided Step 2: full health check with RC2 live gate
  • Run-DeployPreview.ps1 — guided Step 3: dry-run deployment preview, no writes
  • Run-Deploy.ps1 — guided Step 4: live transfer to RC2 with YES confirmation gate

Underlying engine scripts

  • Step5.ps1 - deploy prep functions and role package normalization
  • Step5B_StageFromIncoming.ps1 - stage newest INCOMING package to selected role
  • Step6.ps1 - copy staged role package(s) to RC2 UUID slot folders
  • Step9_HealthCheck.ps1 (health check) - validate mapping, drift, staged files, and optional RC2 slots

Schema

  • step9_healthcheck_report.schema.json (JSON Schema draft 2019-09)

Use this schema with ajv-cli to validate generated health reports.

Prerequisite: AJV (If Needed)

If ajv is not recognized, install it first:

npm install -g ajv-cli

Verify installation:

ajv help validate

If npm is not recognized, install Node.js LTS first, then rerun the commands above.

Quick Commands (Local PowerShell)

Run from repository root. Wrapper scripts prompt for any missing values.

Guided workflow (recommended)

& "./data/rc2/scripts/Run-StageIncoming.ps1"

& "./data/rc2/scripts/Run-HealthCheck.ps1"

& "./data/rc2/scripts/Run-DeployPreview.ps1"

& "./data/rc2/scripts/Run-Deploy.ps1"

With role pre-supplied (no prompt)

& "./data/rc2/scripts/Run-StageIncoming.ps1" -Role Mission_B

& "./data/rc2/scripts/Run-DeployPreview.ps1" -Role Mission_B

& "./data/rc2/scripts/Run-Deploy.ps1" -Role Mission_B

Schema validation (AJV)

ajv validate --spec=draft2019 -s "./data/schema/step9_healthcheck_report.schema.json" -d "$env:USERPROFILE/RC2_Missions/REGISTRY/health/step9_healthcheck_*.json"
